更改语言

您可通过“设置管理器”更改语言（参见“设置管理器”章节）：

  1. 打开IL2_Settings_Manager.exe
  2. 从下拉菜单中选择您偏好的语言（语言以原生名称显示）
  3. 点击“应用”或“确定”
  4. 追踪器将自动以新语言重新生成所有任务简报和 PDF 报告

注意：切换语言时，所有现有的战役简报和PDF报告都会自动以所选语言重新生成。根据您拥有的战役数量，此过程可能需要片刻时间。

📥 安装

步骤 1：下载并安装

  1. 下载最新版本（IL2_CampaignTracker_Setup_v3.0.0_ML.exe.zip）

  2. 解压该压缩包

  3. 运行解压后的IL2_CampaignTracker_Setup_v3.0.0_ML.exe

  4. 按照安装向导中的说明进行操作

安装向导将引导您选择安装目录并配置基本选项。

步骤 2：提取标准战役

⚠️重要提示：追踪器仅能监控位于<IL-2 BoS 路径>\data\campaigns 目录下的战役。标准 IL-2 战役并未直接存储在此文件夹中——它们通过内部的Campaigns.gtp 文件运行。必须先提取这些战役，才能对其进行追踪。

方案 A：通过设置管理器（推荐）

  1. 打开IL2_Settings_Manager.exe
  2. 转到“常规”选项卡
  3. 点击“导入标准战役”
  4. 设置管理器将自动从Campaigns.gtp（以及若存在则从Missions.gtp）中提取战役，并将其导入您的IL-2数据\Campaigns文件夹
  5. 仅添加新的或缺失的战役文件——绝不会覆盖现有文件

方案 B：手动提取

  1. 从https://www.mediafire.com/file/caxpalaudz1hd47/unGTP-IL2.zip下载unGTP-IL2
  2. 解压并将 unGTP-IL2.exe移动到<IL-2 BoS 路径>\data
  3. 将 Campaigns.gtp拖放到 unGTP-IL2.exe上（忽略最后命令提示符窗口中的任何错误警告——所有内容均已解压）
  4. 导航至<IL-2 BoS 路径>\data\(null)\campaigns
  5. 将所有子文件夹复制到<IL-2 BoS 路径>\data\campaigns

🚨注意：若您修改了标准官方战役中的任务，请使用选项 A（设置管理器），该方法绝不会覆盖现有文件。手动复制将替换您修改过的任何文件。

注意：提取官方标准战役的唯一目的是使其可在战役追踪器中使用。请勿修改官方战役。

步骤 3：运行追踪器

从追踪器安装目录运行 IL2_Campaign_Tracker.exe。

ℹ️注意：默认情况下，当关闭《IL-2 BoS》时，追踪器会自动关闭。若要继续使用追踪器，您必须手动重新启动它，或配置 Windows 任务计划程序任务，使其在 Windows 启动时自动运行。

通用设置指南请参见： https://forum.il2-series.com/topic/772-expanded-career-rank-mod/#findComment-4176

🚀 首次运行设置

首次启动追踪器时，设置向导将引导您完成配置：

步骤 1：选择游戏目录

文件夹浏览器将打开。请导航至您的 IL-2 安装目录：

示例：C:\Program Files(x86)\Steam\steamapps\common\IL-2 Sturmovik Battle of Stalingrad

重要提示：请选择主游戏文件夹，而非data\Campaigns子文件夹。

步骤 2：国家验证

追踪器将扫描所有已安装的战役，并尝试为每个战役检测正确的国家。此时将出现一个验证界面，您可以在其中：

  • ✅ 确认自动检测到的国家
  • ✏️ 更正任何识别错误的战役
  • 🚫 排除一战（飞行马戏团）战役

此步骤至关重要，因为晋升和奖项均与国家相关。
ℹ️ 验证/修正国家后，这些战役数据将被写入stock_campaigns.yaml 文件。若您误将国家分配错误，可通过手动编辑stock_campaigns.yaml 中的国家字段进行修正。

WW1（Flying Circus）检测

如果追踪器检测到“飞行马戏团”活动，您可以在本界面将其标记为WW1（忽略）——建议您这样做——以便将其排除在追踪范围之外。

步骤 3：准备开始追踪

配置完成后，追踪器将：

  1. 解码您当前的战役存档文件
  2. 生成初始事件（现有晋升/奖项）
  3. 开始监控变更

检测信号包括：

  • 战役数据中包含一战飞机关键词
  • 战役描述中的“飞行马戏团”/一战关键词

排除机制说明：

  • 在解码和生成事件的过程中，会被跳过已排除的活动。
  • 排除原因存储在campaign_mission_dates.json中，因此追踪器会始终忽略这些活动。
  • 您可以通过重新运行设置（删除campaign_mission_dates.json以及stock_campaigns.yaml 中的相应条目），并在国家验证 GUI 中使用“一战（忽略）”复选框来查看或更改排除项。

🎖️ 晋升与奖励系统

晋升机制

晋升基于所有已完成任务的累计分数（分数值来自 campaignsstates.txt 文件，并由 IL-2 GB 内部规则计算得出）：

单次战役总分 = ∑ 任务分数
晋升分数 = 基础分数 × 军衔加权系数

排名加权系数会根据战役长度调整晋升要求（可在campaign_progress_config.yaml 中编辑）：

"1-10": 1.00 # 短战役（原版战役）
"11-20": 1.15 # 中短战役
"21-30": 1.30 # 中等战役
"31-40": 1.50 # 中长战役
"41-50": 1.75 # 长活动
"51-70": 2.00 # 超长战役
"71+": 5.50 # 史诗级战役（70+ 任务）

这既能防止在长期战役中快速晋升，又能确保短期战役中的公平进度。

ℹ️示例：在 24 个任务的战役中，加权系数为 1.3，因此达到一个需要 1000 分的军衔，实际需要 1300 分（1000 x 1.30）。
当您的累计分数达到或超过 1300 分的晋升门槛时，您将晋升至下一军衔。

🚨重要提示：若修改campaign_progress_config.yaml 文件，请务必保持缩进正确（YAML 格式）。缩进不正确会导致解析错误。

奖项机制

奖项的授予基于campaign_progress_config.yaml中定义的各项标准，并源自《IL-2 BoS》的职业模式。 所有奖项条件均为“或”条件：

标准类型 示例
累计击杀数 8 空战积分 → 一级铁十字勋章
单次任务 单次出击击落7架 → 荣誉勋章
完成的任务 15次任务 → 红星勋章
负伤 飞行员损伤 > 20% → 负伤徽章
随机 + 阈值 高击杀数 + 运气因素 → 稀有勋章

部分奖项设有先决条件（例如：获得一级铁十字勋章前必须先获得二级铁十字勋章）及互斥关系（例如：同一任务中无法同时获得两种伤疤条纹）。

起始军衔偏移

战役可从更高军衔开始（如您所愿）。这对于那些在任务开始时飞行员已是经验丰富军官的战役非常有用。该偏移量可通过以下方式配置：

选项 1：通过设置管理器（推荐）

  1. 打开IL2_Settings_Manager.exe
  2. 转到“战役”选项卡
  3. 双击某项战役以编辑其偏移量
  4. 选择0-7之间的数值

选项 2：在campaign_mission_dates.json 中手动编辑：

"kerch": {
  "country": "Germany",
  "starting_rank_offset": 2,--> 修改此数值（0-7，默认值为0）
  "missions": {...  }
}

注意：较高的偏移量值（最高 7）对于拥有许多低级军衔的英国战役，或者玩家以中队队长身份开始的战役特别有用。

ℹ️注意：您可以根据个人偏好自定义晋升和奖项标准。但强烈建议在进行任何修改前，先备份原始的campaign_progress_config.yaml文件。

📊 任务简报

数据来源

任务简报数据从 IL-2 的任务日志文件（.mlg文件）中提取：

位置：[IL-2 目录]\data\FlightLogs\[任务].mlg

这些二进制文件包含任务期间发生的所有事件的详细记录。 这些二进制文件由mlg2txt.exe转换为 *.txt 文件，随后进行进一步处理。

追踪内容

类别 详情
飞行时间 起飞至降落时长
击杀数 带有时间戳的空中、地面和海上目标
所受伤害 所受命中、来源及伤害百分比
飞行员状态 “损伤” %
状态 着陆、着陆（负伤）、硬着陆、硬着陆（负伤）、跳伞、跳伞（负伤）、阵亡/失踪

任务简报输出

每次任务都会生成两种格式的详细输出：

  1. 游戏内（飞行日志）——按时间顺序排列的事件列表，写入所有 campaigninfo.locale=*.txt文件（每个文件使用相应的语言）
  2. PDF 报告- 完整的战役报告，包括：
    • 按任务分类的击落统计（与游戏内结果界面一致）
    • 按机型划分的击落记录— 汇总表格，展示你在所有任务中按目标机型分类的空中战果（例如：Bf 109 G-6：12，Il-2 1943型：8，等等）
    • 战役统计数据（总分、执行任务数、击落数、负伤情况）
    • 晋升与奖项时间线
    • 带飞行员照片的个人资料封面页（如已配置）

注意：追踪器会将本地化内容写入战役文件夹中存在的每个语言文件。例如，如果您的战役同时包含info.locale=eng.txt和info.locale=ger.txt，则英文文件将包含英文战报，德文文件将包含德文战报。

🧹 任务清理

什么是 takeoffStatus？

IL-2 通过takeoffStatus标志来追踪任务完成情况：

值 含义
takeoffStatus=1 任务已开始但未正常完成
takeoffStatus=2 任务已成功完成

清理界面何时出现

当检测到takeoffStatus=1的任务时，任务清理 GUI 会在追踪器启动时出现。

导致takeoffStatus=1 的常见原因：

  • ❌ 任务目标未完成
  • 🪂 飞行员跳伞逃生
  • 💀 飞行员阵亡
  • ❓ 飞行员失踪（MIA）
  • 💥 IL-2 在任务中坠毁
  • 🚫 强制退出（Alt+F4，任务管理器）
  • 🔌 断电 / 系统崩溃

注：并非所有takeoffStatus=1的任务都属于传统意义上的“失败”。跳伞或阵亡可能是玩家的刻意操作。清理工具会让您选择是否删除这些任务。

📖 AI 故事生成

AI 故事生成功能利用大型语言模型（LLM）为您的职业生涯或战役中的每个任务撰写叙事性战地日记章节。故事采用第三人称历史散文体（而非任务报告风格）撰写，并通过滚动式叙事记忆在不同游戏会话中保持连续性。

此功能同时适用于职业模式（职业服役记录）和战役模式（战役服役记录）。章节将与您的任务简报一同显示在服役记录详情页中。

支持的提供商

您可以使用以下任何一个LLM服务商。每个服务商都需要独立的API密钥，且支持的模型各不相同：

提供者 备注
OpenAI GPT-4o、GPT-4o Mini、GPT-5 等。默认且最简单的配置。
OpenRouter 将多个提供商整合到一个 API 密钥下。非常适合需要多种模型的情况。
Anthropic Claude 3.5 Haiku、Claude 3.5 Sonnet 等。
Google Gemini 2.0 Flash、Gemini 1.5 Pro 等
Microsoft Azure GPT-4o 及其他部署在 Azure 上的 OpenAI 模型。
自定义 任何与 OpenAI 兼容的端点（LM Studio、Ollama 等）。

设置 AI 故事

  1. 打开IL2_Settings_Manager.exe
  2. 转到“AI 故事”选项卡
  3. 启用 AI 故事→ 设置为“是”
  4. 从下拉菜单中选择您的提供商
  5. 输入该提供商的API 密钥
  6. 已知提供商的“基础 URL”会自动填充
  7. 选择或输入模型名称
  8. 可选：启用“自动生成”功能，以便每次任务简报后自动创建一章
  9. 点击“应用”或“确定”

故事生成机制

针对职业模式：

故事内容直接基于从游戏的cp.db数据库中提取的数据以及解析后的任务报告生成：

  • 飞行员信息：军衔、中队、本次出击驾驶的飞机
  • 任务信息：日期、时间（推算得出）、季节（推算得出）、结果、飞行时长、击落数
  • 任务类型：战术角色（例如，前线巡逻、护航轰炸机、轰炸桥梁）源自任务文件
  • 编队：规模和角色（领队或僚机）——针对德国飞行员的德国空军术语（Rotte/Schwarm）
  • 军旅生涯：所有获得的奖章、累计空战击落数、当前军衔
  • 任务相关事件：本次出击后获得的奖章或晋升
  • 中队事件：中队内其他飞行员的晋升、奖章、阵亡/失踪/负伤及调职
  • 历史背景：中队符合时代特征的背景信息，首次检索时通过LLM自动增强
  • 其他职业生涯事件：休养期、中队调动、指挥官任命等叙事性内容
  • 任务间晋升：非飞行日发生的晋升将作为背景信息融入叙述
  • 战区转换：当飞行员调往新战区时，章节采用四段式结构，涵盖前次战役的结束、调动期间（包括任何间隔期间的奖项/晋升）、抵达新单位以及首次出击

针对战役模式：

故事使用战役和任务简报数据：

  • 战役名称及背景文本（源自战役信息文件）
  • 任务简报文本——从.eng任务文件中提取的实际简报（日期、时间及简报正文）将作为故事背景
  • 任务日期、时间、季节、结果、击杀数、飞行时长
  • 击落原因分类——每架战机的击落方式（例如：机枪、碰撞、未知）丰富了叙事内容
  • 追踪器计算的军衔和奖章
  • 根据战役结构推导出的任务类型（例如：护航、拦截、对地攻击、进攻性侦察）
  • 飞行员传记——如果该战役存在飞行员传记文件，则在生成第一章时使用该文件来建立飞行员的背景、性格和故事背景

叙事连续性

每个故事会话都维护着一个滚动更新的叙事记忆，该记忆会在各章节之间延续：

  • 当前军衔和中队
  • 近期任务结果
  • 职业生涯的关键里程碑（晋升、重要奖项）
  • 反复出现的主题（高压下的生存、战斗领导力等）
  • 已确认的空战击落数（来自游戏数据库的权威统计）
  • 此前使用过的章节标题（以避免结构和天气图像的重复）

叙事记忆存储在本地，并作为每个新章节的背景，因此对过去事件的引用、既定的作战背景以及角色发展在整个职业生涯中始终保持一致。

自动生成与手动操作

模式 行为

自动生成 关闭 只有当您在服役记录界面点击“生成”时，才会生成故事

章节管理

在服役记录详情页面中：

  • 查看章节：故事章节将按时间顺序与您的任务简报并列显示
  • 删除章节：点击任意章节的删除按钮，即可移除该章节及其记忆条目。章节编号将自动重排
  • 重新生成：删除后，点击“生成”为该任务创建新章节
  • 上下文预览：通过一个 API 端点，您可以在生成任何任务的故事内容之前对其进行预览（/api/stories/<source>/<id>/context_preview）

🪖 职业服务记录

《职业服役记录》是专为《IL-2》内置职业模式（非战役模式）设计的独立网页应用。它直接从游戏自身的cp.dbSQLite 数据库读取您的职业数据——无需额外的追踪器或数据文件。该应用将呈现您飞行员在所有战区的完整服役历史，包括晋升、奖项、任务、战后简报、战斗统计数据以及 AI 生成的剧情章节。

  • 战区链条：按正确的时间顺序显示您的飞行员曾服役过的完整战区链条（例如：莫斯科战役 → 斯大林格勒战役 → 库尔斯克战役）

    • 伤病休养/医疗休假— 伤病恢复期间，包含起始日期、结束日期及天数
  • 飞行员职务显示：若您的飞行员目前担任指挥职务，该职务将显示在中队名称旁：

    • 执行任务次数及任务结果
    • 飞机使用情况（显示名称已正确解析）

  • 职业生涯PDF报告：生成可打印的完整职业生涯PDF报告——包含各任务击杀表、任务统计数据、附带全尺寸勋章图片的奖项与晋升记录、AI故事章节以及整个职业生涯的汇总统计数据。通过职业生涯详情页中的“下载PDF”按钮触发

❓ 常见问题

为什么我的自定义战役/任务无法被检测到？

答：追踪器会解析任务文件以提取日期和元数据。为确保您的自定义战役能被正确检测，请遵循以下黄金法则：

⚠️重要提示：读取任务需使用英文语言文件

追踪器仅读取英文语言文件（.eng简报 文件和info.locale=eng.txt）来提取任务日期和战役信息。IL-2会在内部存储用户的语言偏好设置，而我们无法检测您在游戏中使用的语言。因此：

  • 每个任务必须配有对应的.eng简报文件（例如，01.Mission 对应01.eng）
  • 您的战役文件夹中必须包含一个用于战役描述的info.locale=eng.txt文件

即使您使用其他语言进行游戏，这些英文文件也必须存在才能使追踪器正常工作。追踪器不会读取.ger、.rus、.fra或其他语言文件来提取日期。

ℹ️多语言输出

当将事件和战报写回您的战役时，追踪器会自动更新所有现有的info.locale=*.txt文件。每个文件将以对应的语言写入：

  • info.locale=eng.txt→ 英文内容
  • info.locale=ger.txt→ 德语内容 (Deutsch)
  • info.locale=fra.txt→ 法语内容 (Français)
  • info.locale=spa.txt→ 西班牙语内容 (Español)
  • info.locale=pol.txt→ 波兰语内容 (Polski)
  • info.locale=rus.txt→ 俄语内容 (Русский)
  • info.locale=chs.txt→ 中文内容（简体中文）

更多详情请参阅“支持的语言”。

任务文件命名：

  • 使用数字前缀表示任务顺序：01.Mission、02.Mission、03.Mission或1.Mission、2.Mission 等。
  • 基于日期的命名方式同样有效：1943-07-04.Mission、1943-07-04a.Mission
  • 支持的扩展名：.Mission、.mission、.msnbin

任务日期检测（在.eng简报文件中）： 追踪器将按以下优先级顺序查找日期信息：

  1. 简报中的Date:字段（例如：Date: 1943年11月4日）
  2. 任务开始时间的“时间：”字段（例如：时间：09:45）
  3. 如果文件名包含日期，则使用该日期（例如：1943-07-04.Mission）

支持的日期格式：

  • 1943年11月 4日
  • 1943年11月4日（不加逗号）
  • 1943年11月4日或1943年11月4日（DD.MM.YYYY 或 MM.DD.YYYY）
  • 1943-07-04（文件名中的 ISO 格式）

战役文件夹结构：

路径：IL-2 BoS\data\Campaigns\您的战役名称\
    ├── info.locale=eng.txt    （必填 - 用于读取战役描述）
    ├── info.locale=ger.txt    （可选 - 追踪器在此写入德语内容）
    ├── info.locale=fra.txt    （可选 - 追踪器在此写入法语内容）
    ├── info.locale=rus.txt    （可选 - 追踪器在此写入俄语内容）
    ├── 01.Mission             (任务文件)
    ├── 01.eng                 (必填 - 带日期/时间的英文任务简报)
    ├── 02.Mission
    ├── 02.eng                 (必填 - 带日期/时间的英文任务简报)
    └── ...

国家检测： 追踪器通过以下方式自动检测您的国家/阵营：

  1. 任务文件中的飞机名称（例如，bf109 → 德国，spitfire → 英国）
  2. 包含国家标识符的部队名称
  3. 您可以在首次运行时通过“国家验证器”图形界面手动设置/更正，或稍后在stock_campaigns.yaml中手动调整

常见问题：

  • 缺少.eng简报文件 → 无法提取日期（任务仍将作为“任务 1”、“任务 2”等进行追踪，但没有日期信息）
  • 缺少info.locale=eng.txt→ 无法获取战役描述，追踪器无法读取战役信息
  • 简报中日期格式不标准 → 请使用上述支持的格式之一
  • 战役文件夹名称中含有特殊字符 → 请避免使用变音符或特殊符号
  • 一战战役（Flying Circus）→ 默认被排除（参见“一战检测与排除”章节）

问：我可以同时运行多个追踪器实例吗？

答：不可以。每次只能有一个实例监控您的战役。

问：追踪器会修改我的《IL-2》安装吗？

答：追踪器仅修改：

  • 战役info.locale=eng.txt文件（添加“事件”部分）
  • 在 usersave 文件夹中创建备份文件

它不会修改任何游戏可执行文件或核心文件。

问：这在模组中能正常工作吗？

A:是的，只要模组采用标准战役结构即可。自定义战役会在首次运行设置时被自动检测。

问：我可以手动编辑配置吗？

A:可以，但我们建议使用“设置管理器”（IL2_Settings_Manager.exe）进行大部分修改。它提供了一个用户友好的界面，并在需要时自动处理文件再生成。

若需进行高级自定义，可手动编辑campaign_progress_config.yaml文件以：

  • 调整晋升分数阈值
  • 修改奖项标准
  • 添加自定义奖项
  • 更改排名加权系数

⚠️ 在手动编辑配置文件之前，请务必创建备份。

问：如何重置所有设置？

A:删除以下文件并重启追踪器：

  • campaign_mission_dates.json
  • campaign_popups_seen.json
  • campaigns_decoded.json
  • campaign_events.json

问：是否支持多人游戏？

A：本追踪器专为单人职业战役设计。多人游戏任务生成的保存数据结构与之不同。

问：为什么需要重启 IL-2 才能看到新事件？

A:IL-2 在游戏启动时会加载战役描述文件（info.locale=eng.txt）并将其缓存至内存中。追踪器所做的更改虽已写入该文件，但在重启 IL-2 之前不会在游戏中显示。不过，当您获得晋升或奖项时，仍会立即看到弹出提示。

问：如果我手动删除备份文件会怎样？

答：备份索引（campaignsstates_hash_index.json）仍会引用该文件，但“还原”界面将跳过实际备份文件缺失的备份。

问：我可以在《Flying Circus》（一战）中使用追踪器吗？

A：默认情况下，系统会检测并排除“飞行马戏团”战役。该追踪器专为二战战役设计，不包含一战时期的军衔或奖章。您可在国家验证步骤中控制排除项（勾选一战“忽略”复选框），但一战战役将无法获得历史准确的军衔或奖章。

问：我可以将追踪器与 Pat Wilson 的战役生成器（PWCG）配合使用吗？

答：不可以——本追踪器既无法与PWCG配合使用，也不会对其造成干扰。

问：使用追踪器需要联网吗？

答：不需要——追踪器及两份服役记录均可完全离线运行。仅在生成AI故事章节时需要网络连接（以连接您配置的LLM服务商）。所有其他功能——监控、战后简报、晋升、奖项、PDF报告以及服役记录界面——均可在无网络连接的情况下使用。

问：AI故事应该使用哪个LLM模型？

答：对于 OpenAI，gpt-4o-mini在质量与成本之间提供了最佳平衡。对于 OpenRouter，openai/gpt-4o-mini是一个可靠的默认选择。对于 Anthropic，claude-3-5-haiku-20241022速度快且功能强大。任何能稳定返回 JSON 格式，并能生成每条回复 150–400 字连贯散文的模型都能很好地工作。

问：生成AI故事需要多少成本？

答：成本完全取决于您的服务提供商和模型。一个典型的职业故事章节（产出180–380个单词）每项任务大约消耗1,500–3,000个令牌。按gpt-4o-mini的定价（截至2025年），每章成本不到0.01美元。 使用该模型撰写完整的100个任务的职业生涯，总成本约为0.50–1.00美元。
